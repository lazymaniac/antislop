# Managed workspace lifecycle

Design §11.1 requires default worktree execution, explicit in-place choice, protected user changes, independently identified integration candidates and separate delivery operations. Worktree tasks require background source inspection, explicit private-candidate preparation and separately approved activation before execution. Source transfer is now separately scoped; general candidate integration remains incomplete.

## Source transfer

After accepting the complete independently verified team result, use the chat guide or palette to inspect source delivery, then review and approve the exact transfer. CLI equivalents are `antislop inspect-delivery STATE_DIR RUN_ID` and `antislop deliver-source STATE_DIR RUN_ID --approve-scoped`. Inspection starts no agents and writes no source files. It refuses stale proofs, changed source/candidate state, unresolved annotations, unsupported effects and unrelated local changes that have not been integrated and revalidated. Runtime ownership proofs admit text writes, creations and deletions through authenticated managed edits. Creation/deletion require a captured containing directory; the directory remains one declared input and every changed leaf stays within the assigned editable scope. Exact standalone file inputs continue to support writes. The lower-level file transport also handles binary data and relative links; those capabilities do not authorize unsupported runtime effects.

Transfer retains displaced entries in `.antislop-delivery-<operation-id>` inside the source root. It preserves original file permissions and ownership, records intent before each change and refuses to overwrite a destination that appears during installation. Descriptor-relative operations refuse symlinked parents and Git administration paths. The mechanics follow the POSIX [link/linkat](https://pubs.opengroup.org/onlinepubs/9699919799/functions/link.html), [rename/renameat](https://pubs.opengroup.org/onlinepubs/9799919799/functions/rename.html) and [open/openat](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html) contracts. This does not isolate arbitrary external processes or prevent writes through already open descriptors.

Interrupted transfer is never replayed automatically. The UI exposes observed targets and retained backups, restoration of an absent target without overwriting a new user entry, and a separately approved acknowledgement of current effects. Recovery does not infer provider authorship from matching bytes. Backups remain retained; automatic cleanup and handling them in later repository-wide observations remain open. Commit, push and publication are separate operations.

Git observation uses NUL-separated `ls-files`/`ls-tree` output and raw `hash-object --no-filters` input, following the [ls-files](https://git-scm.com/docs/git-ls-files), [ls-tree](https://git-scm.com/docs/git-ls-tree) and [hash-object](https://git-scm.com/docs/git-hash-object) contracts. Optional locking is disabled to preserve the index during reads ([status background refresh](https://git-scm.com/docs/git-status#_background_refresh)). The source reader does not invoke checkout or commit. Future worktree creation must account for callback behavior: Git documents the post-checkout hook for worktree add unless `--no-checkout` is used ([hooks](https://git-scm.com/docs/githooks#_post_checkout)).

A worktree isolates working files while Git administration and other machine resources remain shared. Environment isolation and resource allocation therefore retain their own acceptance requirements. A source scope digest and a Git checkout do not grant effect permissions; the runtime's actual approvals, observations and independent quality gates remain required.
